# wasm-rtos-tests

This repository contains isolated integration tests for `wasm-rtos`.

Every test owns its guest program, native runner, generated WASM module, and log:

```text
tests/
  queue_api/
    queue_api.c
    main.c
    queue_api.wasm
    queue_api.log
  ...
  support/
    test_support.c
    test_support.h
    test_runner.c
    test_runner.h
```

There is no repository-level `main.c`, `build/`, or `logs/` directory.

## Test contract

A test directory must contain:

- `<test_name>.c`: the WASM guest program.
- `main.c`: the native host runner configuration for that test.
- `<test_name>.wasm`: generated by CI next to the guest source.
- `<test_name>.log`: generated by the test runner in the same directory.

`tests/support/` contains reusable file-loading, logging, assertion, and runner helpers. It does not enumerate test directories. Each test selects its own behavior in its local `main.c`.

## Running tests

The GitHub Actions workflow discovers test directories by searching for `tests/*/main.c`. Each directory is compiled and executed independently, so one test cannot depend on another test's process state.

Generated `.wasm` and `.log` files are uploaded as workflow artifacts. On non-pull-request runs, changed outputs are also committed next to their test sources.

## Adding a test

Create a directory named after the test:

```text
tests/new_test/
  new_test.c
  main.c
```

The workflow automatically builds:

```text
tests/new_test/new_test.wasm
tests/new_test/new_test.log
```

No central workflow test list needs to be edited.
